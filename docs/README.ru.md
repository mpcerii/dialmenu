## О чём это

У большинства механических клавиатур есть поворотная ручка, жёстко
привязанная к громкости. DialMenu перехватывает эти сигналы до того, как их
увидит система, и вместо этого открывает меню: **поворот выбирает, нажатие
запускает.**

Сама клавиатура при этом не меняется. Без перепрошивки, без прошивки, без
драйверов. DialMenu только слушает — отключите клавиатуру или закройте
программу, и всё снова как было.

```
   Поворот ──▶ HID-отчёт ──▶ DialMenu ──▶ действие
                                │
                                └──▶ система больше не видит клавишу громкости
```

## Возможности

<img src="../docs/settings.png" alt="Окно настроек со списком команд, редактором и предпросмотром кольца">

- **Радиальное меню** — стеклянные поверхности, монохром, один подсвеченный
  контур выбора. Команд сколько угодно; кольцо растёт вместе с ними.
- **Четыре темы кольца** в двух яркостях каждая, плюс светлая и тёмная по
  выбору или по системной настройке.
- **Немецкий и английский**, переключаются без перезапуска.
- **Программы, папки, сайты** — включая выбор из действительно установленных
  программ вместо ввода путей.
- **Сочетания клавиш** — `Ctrl+Alt+M`, `Win+D`, `Alt+F4` и всё между ними.
- **Макросы** — цепочки сочетаний, текста и пауз в одну последовательность.
- **Discord** — выключение и заглушение микрофона с кольца.
- **Несколько профилей** и **несколько устройств**.
- **Автоматическое определение устройства** — три поворота вправо, три влево,
  одно нажатие. DialMenu находит ручку сам, без ввода идентификатора.
- **Свободное размещение** — двенадцать позиций плюс монитор под курсором.

## Установка

Windows 10 или 11, .NET Framework 4.8 (предустановлен в Windows 11).
Установщика нет — DialMenu это один `.exe`.

1. [Скачайте последнюю версию](../../releases/latest)
2. Положите `DialMenu.exe` в любую папку
3. Запустите — откроется окно настроек

Дальше нужно два щелчка: в разделе **Устройства** нажмите *Начать
определение* и поверните ручку три шага вправо, три влево, затем нажмите один
раз. После этого соберите нужное на кольце в разделе **Команды**.

## Первые шаги

**Какие клавиатуры подходят?**
Любые, чья ручка посылает стандартные клавиши громкости — это большинство.
Благодаря автоматическому определению ничего вводить не нужно.

**Ручка ничего не делает.**
Запустите помощник в разделе **Устройства** ещё раз. Индикатор («вправо 1/3 ·
влево 0/3») показывает, приходят ли вообще сигналы. Если он остаётся на нуле,
клавиатура посылает то, что не приходит как мультимедийная клавиша.

**Где настройки, если ручка занята меню?**
В области уведомлений панели задач. Один щелчок там открывает окно.

**Можно вернуть громкость?**
Да: закройте DialMenu из области уведомлений или снимите флажок в разделе
**Поведение**. Собственные клавиши громкости клавиатуры работают в любом
случае.

## Настройка

Всё лежит в `%APPDATA%\DialMenu\config.json` — читаемо и версионируемо.
Профиль можно скопировать и передать.

## Сборка из исходников

<img src="../docs/ring-light.png" width="260" align="right" alt="Кольцо в светлом режиме">

Требуется Windows с .NET Framework 4.8 и MSBuild (входит в Visual Studio или
Build Tools).

```powershell
.\build.ps1
```

Готовый файл окажется в `bin\Release\DialMenu.exe`.

Без Visual Studio достаточно копии MSBuild, которая уже есть в Windows:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe' DialMenu.csproj /p:Configuration=Release
```

## Как это работает

Два механизма сцеплены между собой:

**Raw Input** читает необработанные HID-пакеты. Из них выводится, какой шаг
был повёрнут и когда нажата ручка — независимо от того, какие клавиши делает
из них система.

**Перехватчик клавиатуры** забирает возникшие клавиши громкости. Он пропускает
их только тогда, когда они *не* пришли непосредственно от собственного
устройства. Клавиши громкости других программ и клавиатур не затрагиваются.

Оба работают в отдельном потоке. Причина измерена: если перехватчик не
ответит за 300 мс, Windows отбрасывает клавишу, и громкость всё равно
меняется. Если он работает в потоке интерфейса, происходит именно это, как
только что-то рисуется.

Нажатия, созданные самой программой, помечаются и никогда не перехватываются —
иначе она заблокировала бы себя.

## Платформы

| | Состояние |
|---|---|
| Windows 10 / 11 | готово |
| macOS | в планах |
| Linux | в планах |

Оба механизма, на которых держится DialMenu, привязаны к платформе и не имеют
прямого аналога в macOS и Linux. Поэтому путь туда не порт, а вторая
реализация: в Linux через `evdev` и `uinput`, в macOS через `IOHIDManager` и
`CGEventTap`. Само колесо, темы и логика управления от этого не зависят и
переносятся.

## Ограничения

- **Только устройства со стандартными мультимедийными клавишами.** Прошивку с
  собственным протоколом перехватить нельзя.
- **Один шаг будит меню, но ещё не выбирает.** Иначе первый шаг выполнял бы
  двойную работу.
- **Системная громкость недоступна на ручке**, пока DialMenu запущен.
  Собственные клавиши громкости клавиатуры продолжают работать.
- **Подписи в кольце** появляются только до шести пунктов. Дальше в дугу не
  помещается ни одно слово — остаются значки.
